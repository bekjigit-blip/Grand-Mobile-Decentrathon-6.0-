# Grand Mobile Support Copilot (Decentrathon 6.0)

> **Толық жұмыс істейтін офлайн NLP Support Copilot MVP**  
> Grand Mobile ойыншыларының өтініштерін (report/appeal/ticket) автоматты түрде санаттау, басымдықты белгілеу, сервер ережелерінен (11 бөлім, 266 тармақ) дәлелді цитаталар табу және қауіпсіз жауап жобасын әзірлеуге арналған жүйе.

---

## 1. Негізгі шектеулерге сәйкестік (Compliance)

- **100% Offline & CPU Only**: Сыртқы LLM API (OpenAI, Gemini, Claude, т.б.), API кілттері, Manifest, бұлттық embeddings немесе ақылы inference мүлдем қолданылмайды.
- **Жоғары жылдамдық (p95 ≤ 5 секунд талабы)**: Оңтайландырылған `scipy.sparse.csr_matrix` TF-IDF арқылы бір өтінішті өңдеу уақыты **p50 = 3.23 мс**, **p95 = 3.64 мс** (~190 өтініш/секунд).
- **Сыртқы шығын**: **$0.00 (Zero API cost)**.
- **Жергілікті HTTP қызметі**: Тапсырмадағы нақты JSON спецификациясы бойынша `POST /triage` және `GET /health` сервисі жұмыс істейді.
- **Деректердің құпиялылығы**: Бастапқы деректер (`data/train.jsonl`, `data/valid.jsonl`), құрылған индекстер (`index_cache/*.joblib`) және SQLite базасы `.gitignore` арқылы жария репозиторийден толық оқшауланған.

## 3. Тапсырма талаптарын шешу жолдары

### 3.1. Қайталанатын ереже нөмірлері (section_id + ref)
Сервер ережелерінде әр бөлім өз тармақтарынан басталады (мысалы, 1.1, 2.1, 3.1 немесе бөлім ішіндегі қайталанулар). Тек `ref` бойынша сөздік жасағанда ережелер бір-бірін алмастырып жібермес үшін, жүйеде ішкі бірегей кілт ретінде **`f"{section_id}::{ref}"`** қолданылады. Бұл ретте ойыншыға техникалық ID көрсетілмейді: `draft_reply.cited` өрісінде таза тармақ нөмірі (`["2.1"]` немесе `["GZ 3.1"]`), ал жауап мәтінінде бөлімнің толық атауы шығарылады.

### 3.2. Көптілділік және Қазақша CP1251 өңдеу
- TF-IDF өздігінен тілді аудармайды. Сондықтан `app/lexicon.py` ішінде қазақша (`өлтірді`, `көлікпен басты`, `донат келмеді`, `ұрланды`, `алдап кетті`) және өзбекше терминдер орысша RP ережелерінің түйінді сөздеріне байланатын семантикалық көпір арқылы кеңейтіледі.
- `app/cp1251_fixer.py` қазақша бүлінген мәтіндерді контекстпен түзейді (`сєлемет` → `сәлемет`, `кґлік` → `көлік`, `бўл` → `бұл`, `ґлтір` → `өлтір`), украинша сөздердегі `є` және `ї` әріптерін жөнсіз өзгертпейді.

### 3.3. Басымдықтар (Priority) және Адамға бағыттау (Needs Human)
Басымдықтар қатаң құжатталған кезекпен анықталады:
1. **p0 (Критикалық)**: Аккаунт ұрлануы / бұзылуы (`account_access` немесе мәтіндегі взлом белгілері). Әрқашан `needs_human: true`.
2. **p1 (Жоғары)**: Нақты ақша төлемдері мен Grand Coins түспеуі (`donation_payment`), серверге қауіп төндіретін рванка/ауыр читтер, мүлікті алдап кету (`player_report_scam`). Төлемдер мен скамдар әрқашан `needs_human: true`.
3. **p2 (Орташа)**: Ойыншылар арасындағы әдеттегі шағымдар (DM, DB, Green Zone, NonRP, чат), әкімшілікке шағымдар, жазаны қайта қарау (апелляция), ойын багтары. Әкімшілік және апелляция әрқашан `needs_human: true`.
4. **p3 (Төмен)**: Жалпы сұрақтар (`in_game_help`), жұмыс/права табу, ойыншылар ұсыныстары.
> **Маңызды**: Тіркеменің болуы (`images_count > 0`) өтінішті автоматты түрде p1 жасамайды! Тіркеме тек дәлелдеме қосылғанын білдіреді. Егер санат бойынша ұқсастық төмен немесе екіұшты болса (`margin < 0.05`), жүйе автоматты түрде адам тексеруіне белгілейді.

### 3.4. Қайталану және Спам (Deduplication)
- Егер `reporter_hash` немесе `created_at` жоқ болса, жүйе ойдан басқа ойыншымен қайталанды деп болжамайды!
- Әртүрлі ойыншылардың бірдей қысқа мәтіндері («Сәлем көмек керек») біріктірілмейді.
- Тек **бірдей ойыншыдан** соңғы 1 сағат (3600 сек) ішінде ұқсастығы жоғары өтініш келгенде ғана `is_spam_or_duplicate = true` деп белгіленіп, қайталану шаблоны беріледі.

### 3.5. Деректер ағып кетуінен қорғау (Data Leakage Protection)
- `app/predict.py` кіріс өтінішті өңдеу алдында `verdict`, `punishment`, `violation`, `status`, `admin_reply` өрістерін толық тазартады.
- Бағаланатын өтініштің өзі немесе көшірмесі дайын жауап ретінде қайтарылмайды.

## 4. Жүйені іске қосу нұсқаулығы (Windows & Linux)

### 4.1. Тәуелділіктерді орнату

**Windows (cmd / PowerShell):**
```cmd
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

**Linux / macOS:**
```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 4.2. Индекстерді құру
```bash
python -m app.build_index
```
*(Индекс `index_cache/` папкасына сақталады және қайта іске қосқанда 0.005 секундта дигіден жүктеледі).*

### 4.3. Пакеттік болжау (Batch Predict)
Тапсырмада талап етілген екі команда:
```bash
python -m app.predict --input data/valid.jsonl --output pred.jsonl
```
немесе Make арқылы:
```bash
make predict IN=data/valid.jsonl OUT=pred.jsonl
```
*(1000 валидациялық өтініш 7.3 секундта, ~136 өтініш/сек жылдамдықпен 100% сәтті өңделеді).*

### 4.4. Жергілікті HTTP сервисін іске қосу
```bash
python -m app.server
```
Сервис `http://127.0.0.1:8005` (немесе веб-интерфейс проксиі арқылы `http://127.0.0.1:3000`) адресінде іске қосылады:
- `POST /triage` — өтінішті бағалау (Decentrathon 6.0 ресми JSON келісімшарты)
- `GET /health` — жүйе денсаулығы, жад, нұсқа және индекс күйі

### 4.5. Тестілеу (Pytest)
```bash
python -m pytest -v tests/
```
*(Барлық 20 тест: қайталанатын ережелер, семантикалық шек арқылы қате цитаталарды қайтару, human routing, cp1251, дедупликацияның 1 сағаттық терезесі, SQLite әкімшілік әрекеттері, kind/messages адаптері және JSONL қатар реті 100% сәтті өтеді).*

## 7. Қалған шектеулер мен ескертулер
1. **Gold Labels жоқ**: Бастапқы train/valid деректерінде ресми белгіленген category/priority болмағандықтан, supervised классификатор ретінде жаттандырылған метрикалар ойдан жазылмады. Шешім көптілді санат прототиптері, түсіндірілетін ережелер және TF-IDF ұқсастығы негізінде жұмыс істейді.
2. **Бейнежазба мазмұнын талдау**: `images_count` және тіркемелер тек факт ретінде тіркеледі; скриншоттың немесе бейненің шынайылығы офлайн CPU NLP шеңберінде тексерілмейді, сондықтан маңызды дәлелдемелер әкімші қарауына бағытталады (`needs_human: true`).
